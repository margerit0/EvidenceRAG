## 用户已经明确的设计要求

> 视觉上采用清爽的中性底色、明确的品牌强调色和统一的状态色，兼顾浅色与深色；
> 精修字体层级、间距、图标和细节，让信息紧凑但不拥挤。
> 优先使用连续分区、对象列表、主从详情与就地操作，避免卡片套卡片、KPI 卡墙
> 和传统后台模板感。
>
> 主动选用并适配 Aceternity UI、shadcn/ui、Magic UI、Origin UI 等成熟组件，
> 结合轻量动效和贴合业务的视觉资产，形成有辨识度的体验。
> 动效既服务反馈与空间连续性，也提升交互质感，但不能遮挡内容、挤动布局
> 或拖慢操作。

现有实现采用冷灰底色、青绿色强调色、独立语义状态色，左侧问题与答案、
中间执行图和时间线、右侧步骤／证据／运行详情。这是待评审的当前方案，
布局比例、视觉层级和具体色值都可以被质疑和改进。

最初参考图是 `start → agent → tools → agent / end` 的循环图。
用户需要的是可感知的执行状态与路径，不是完整工作流编排器。

建议查看：

| 场景 | 审查重点 |
| --- | --- |
| 桌面浅色、深色初始页 | 第一眼焦点、层级、字号、对比度、分区比例与空白 |
| 完整调查运行中 | 当前节点是否醒目，动效是否影响阅读，状态变化是否挤动布局 |
| 完整调查结束 | 答案、引用与证据的关系，阅读顺序，工具重复调用是否容易理解 |
| 点击第二次搜索 | 具体调用的选中状态，图节点与时间线、检查器之间的联系 |
| 点击答案引用 | 证据是否容易找到，原文是否便于阅读，详情区宽度是否合理 |
| 追问、证据不足、超时、预算耗尽 | 语义是否清楚，状态是否仅依赖颜色，下一步操作是否自然 |
| 停止与历史列表 | 反馈是否及时，历史选择是否顺畅 |
| 窄屏 | 排列顺序、图中文字、触控目标、页面长度与滚动成本 |

参考视口：桌面 `1440 × 1000`，窄屏 `390 × 844`；可加看常见笔记本高度。

## 需要准确保留的语义与边界

- 图表示可能的动作路径；同一节点可以运行多次。时间线保存各次调用，
  图节点显示该类型的最近一次调用，不能把图误读成固定线性流水线。
- SSE 由后端提供真实的开始和完成事件。旧服务只有结束后的执行记录；
  页面不会把旧记录的相对时间伪造成单步耗时。
- 搜索候选不等于已读取证据。完整证据随最终结果返回；当前没有逐字答案流。
- 真实运行停止是合作取消：显示“已请求停止”，不能宣称阻塞调用或计费已立即停止。
- 演示不是模型效果证明。格式／引用校验通过，不代表答案独立事实验收通过。
- 运行历史只保存在本页面内存，刷新后清空；持久多轮会话尚未实现。
- 真实 chat、embedding、rerank 和付费试次仍暂停。不读取凭证、不联网补充真实语料。
- 本轮审查不需要修改 Agent 提示词、预算、评测或后端合同。

## 建议的审查产出

先实际查看页面，再按影响排序给出约 5–8 项具体发现。每项包含：
所在区域／状态、观察证据、对观看或操作的影响、建议改法、优先级。
区分可读性／可用性缺陷与审美偏好；没有截图或交互证据的推测要说明。
不要用笼统的“更现代”“更高级”、虚构的评分或泛泛的设计清单代替具体建议。

最后给出一轮有限的优化范围，说明哪些现有设计值得保留。必要时提供局部前后
对照草图，帮助用户判断变化；不要在第一轮审查中重写整站或扩大功能范围。

上一轮已通过 1,735 项 Python 测试、13 项前端单元测试、9 项浏览器场景检查，
并检查过生产构建与浅深／窄屏截图。这是功能与基本布局的基线，不代表视觉设计
已经最优。纯审查无需重跑全套测试；实施后运行与变更相关的检查。
