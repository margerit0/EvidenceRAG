# 有预算的必要信息判定与问题覆盖实验

基于 `5814e5f`，仍在 `feat/document-investigation-agent`。先前三个 dev 输出虽格式有效，
但存在环境事实扩写、机制/风险遗漏和用分支建议代替追问。本轮将这些决定显式记录，
不把更多自然语言提醒当作已验证的解决方案。

服务与对照入口增加默认关闭的 `--agent-plan-investigation`，与答案复核开关独立。
关闭时保留既有提示词、动作路径和 Agent 指纹；开启时使用独立规划合同与指纹。

当前初始规划提示词为 `document-investigation-planning-v2`。真实流式响应曾在 facts
对象中加入空 description；v2 明确要求项四个字段、事实项仅 id/quote，并区分未来目标
与当前观察事实。描述须列出待调查事项，不能在读取证据前断言机制或损失。严格解析器
保持原样，额外空字段仍拒绝，不自动清理。提示词修复效果以独立新试次审核为准。

## 流程与执行约束

1. 首次模型调用只看问题，列出固定编号的必答项，以及用户明确提供的事实。每项用
   问题原文的连续片段定位；事实也必须逐字来自问题，不能自行改写环境状态。
2. 后续每次决策同时提交全部必答项的覆盖情况、关键环境依赖和下一动作。已覆盖项
   必须引用已读取证据的逐字片段；候选摘要、未知 ID 和改写的引文不能代替完整证据。
3. 依赖必须有已读文档支持。已知依赖指向首次固定的用户事实编号；未知依赖提供一个
   必要追问。发现已声明的关键未知依赖时，程序直接结束为 `clarification_needed`，
   不执行同一响应里的分支答案或后续工具动作。
4. 发布答案要求所有固定必答项都声明已覆盖，并映射到实际答案段落；覆盖引文必须
   出现在所映射段落的引用中，每个段落至少对应一个必答项。覆盖不全时保留缺项编号
   并继续在原预算内调查。格式/引文合同错误仍直接停止，不自动修补 JSON。

所有规划与决策调用共享原模型步数、输入预算和调用边界时长；不增设隐含免费步骤。
搜索/读取额度不增加。现有取消、超时、失败与答案复核仍有效。开启规划并不自动开启
答案复核；若同时启用，两道检查均须通过。

## 审计与能力边界

启用时在请求结果的专用事件中保存简短的计划与覆盖记录，供本地试次审核；普通时间线
只展示动作和状态。记录包含任务/证据派生文本，继续放在 Git 忽略的试次目录，不进入
服务器遥测或仓库。模型内部思考与凭证不记录；后续提示词只带最新覆盖记录，避免完整
历史审计内容重复膨胀。

执行后补充固定校验诊断：失败规划事件的 `error_code` 只包含允许的规则码，例如
`extra_fields`、`question_quote`、`evidence_id`；不记录被拒绝正文、未知字段名或之前的
覆盖记录。公共状态仍为 `invalid_action`，不放宽合同、不自动修补。诊断合同进入
规划开启时的指纹；规划关闭时仍保留基线指纹。执行前没有细分码的旧失败不能追溯。

Python 能认证引文出处、编号完整性、未知依赖的路由和段落映射，不能认证模型是否
列全问题要求、识别了真正必要的依赖、理解了条件范围或正确判断语义支持。逐字存在
不是蕴含证明，仍需独立模型审核。测试使用原创合成场景，不写入 TiDB/CRUD 语料。

本轮离线门禁后仅验证原三条 dev 各一次：GLM 5.3 / high / 无显式输出上限，最多十次
总尝试，规划开启、答案复核关闭，沿用原任务、索引和调查预算；使用新计划与 run-id。
保留失败，不扩大 dev，不使用冻结 test，不自动追加 off/on 对照。

三试次实际均在首次规划阶段失败，未检验覆盖门禁的真实语义效果。随后用户授权的
流式诊断中，跨文档 GLM 单次规划完整且结构合格，DeepSeek 单次仍为 504；产品尚未
接入流式。详见[最新交接](agent-iteration.md)，不能将该诊断写成完整调查通过。
