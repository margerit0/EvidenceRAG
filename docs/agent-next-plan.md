## 1：正式化离线审核与报告

1. 先只读运行旧入口，记录报告、原始试次、审核标签与保护文件指纹作为迁移基线：

   ```powershell
   .venv/Scripts/python.exe indexes/agent_eval/v2/review/report_glm53_stream_agent.py --check
   .venv/Scripts/python.exe indexes/agent_eval/v2/review/report_glm53_stream_plan_v2.py --check
   ```

2. 复用 `certify_run()` / `validate_reviews()` / `quality_report()`，抽取本地报告器中
   通用的计划与源码快照摘要认证、证据重建、陈述审核关联检查。只迁移通用逻辑，
   不把内嵌真实任务、答案或语料的临时脚本整体纳入仓库。
3. 增加明确的描述性报告模式：报告任务/状态分布、审核来源、陈述支持分子分母、
   调用次数与耗时；单来源不生成 CI、p 值或显著性结论，0/0 明确为无可评估陈述。
   保持既有聚类报告合同和重算结果；新合同或新字段的兼容策略需先确定。
4. 旧档缺少新认证字段时标明认证范围与不可验证项，不猜测、不回写。
   对所声明合同的必需材料缺失或摘要不匹配，应失败而非降级为成功。
5. 用原创合成材料覆盖缺档、重复 JSON 键、非有限数、混合配置、陈述/引用不一致、
   单来源及多来源报告。新通用入口与旧报告器对照重算，使用独立输出目录。

验收：断网且无 `.env` 也能完成认证与重算；旧两组报告的既有事实与标签保持一致；
旧文件保护指纹不变；审核者类型、认证范围及统计限制能从报告直接读出。

## 2：建立离线失败回放

1. 定义回放清单：输入文件摘要、解析合同、被测代码指纹、可用证据/请求状态、
   历史记录的终态及预计检查项。首先盘点哪些旧失败实际有足够材料。
2. 最终响应回放复用现有解析与校验逻辑，优先复现已保存的额外字段错误；
   输出当前回放终态，并与历史记录分开呈现。解析器变更后不伪称仍在重放旧代码。
3. 合成协议回放复用 `StreamCollector` 和现有流式测试，覆盖缺少 stop/DONE、
   错误事件、模型身份不匹配、截断、超时、取消及预算耗尽；时间由可控时钟驱动。
4. 仅有事件类型、耗时、字符数的历史日志不能还原真实 SSE；缺少正文或必要状态时
   输出不可回放及原因。新回放使用独立标识与目录，不覆盖历史响应或补写证据。

验收：两类回放明确标识；摘要漂移/缺档可检测；预期的协议及预算边界可稳定复现；
测试阻断 socket/provider 调用后仍通过。一次回放成功只证明对应检查路径被复现。

## 3：正式化运行与故障诊断

1. 将本次已验证的本地启动方式整理为仓库可复用入口，配置通过参数传入；
   只清理子进程代理环境，保留 TLS 校验，不依赖特定 `.research_tmp` 路径或内嵌密钥。
2. 提供分层检查结果：本地服务、前端代理、TLS、认证、模型可见性。
   默认检查不触发生成；显式执行最小生成时固定请求数量与预算。
3. 复用已有错误分类，补足每次 HTTP 尝试的类别、状态码、耗时和重试次数。
   将模型决策次数与 HTTP 尝试次数分别统计，旧记录缺字段显示未知。
4. 前端先复用现有检查器，仅增加能帮助用户操作的提示与诊断编号；详细分类留在
   脱敏服务日志。分别呈现调用、解析、调查终态与独立质量审核状态。

验收：使用合成失败覆盖各类别与重试边界；日志不包含密钥、请求正文或内部思考；
无代理环境和 TLS 校验有回归覆盖；健康检查成功不能被呈现为模型调用成功。

## 4：定向调查质量验证

1. 先离线核对已保存失败、原 dev 任务及审核条件，明确此次只改进一个可观测问题，
   例如必要追问或跨文档必答项遗漏；记录当前基线与拟验证改动。
2. 生成新的运行计划与源码快照，固定任务、模型、索引、预算、方法配置和停止条件。
   优先处理原跨文档任务；该项独立验收通过后，再安排原简单题与追问题。
3. 采用新 run-id 保存全部成功和失败；逐项审核必要信息、事实/目标区分、引用支持、
   机制/风险覆盖和追问恰当性。模型审核与人工审核分开统计。
4. 报告任务成功率、陈述支持分子分母、失败类型、实际调用/重试与耗时；供应商缺少
   可靠账单时金额记为未知。配对比较遵循现有来源组统计限制。
